# 국립해양조사원 조위 자료 자동 수집

부산(DT_0005) 2022년 9월의 관측 조위와 천문조 예측 조위를 날짜별로 내려받지 않고 API로 모으는 도구입니다.
학생용 웹앱은 이 도구가 미리 만든 파일만 읽습니다. 학생이 앱을 쓸 때 외부 API를 호출하지 않으며, 인증키도 앱에 들어가지 않습니다.

## 사용하는 공식 API (2026-11-08 확인)

바다누리 해양정보 서비스의 [활용 가이드라인](https://www.khoa.go.kr/oceandata/openapi/odmi/apiGuideline.do)에 따르면, 국립해양조사원 오픈API는 공공데이터포털(data.go.kr)을 통해 제공됩니다.

| 용도 | 공공데이터포털 서비스 이름 | 데이터셋 | 호출 주소 | 주요 값 |
|---|---|---|---|---|
| 관측 조위(품질처리된 시간별 성과) | 해양수산부 국립해양조사원_1시간 조위(조석성과) | [15156017](https://www.data.go.kr/data/15156017/openapi.do) | `https://apis.data.go.kr/1192136/hourlyTide/GetHourlyTideApiService` | `obsrvnDt`, `tdlvVl`(조위값, cm) |
| 천문조 예측 조위 | 해양수산부 국립해양조사원_조석예보(시계열) | [15156022](https://www.data.go.kr/data/15156022/openapi.do) | `https://apis.data.go.kr/1192136/tideFcstTime/GetTideFcstTimeApiService` | `predcDt`, `tdlvHgt`(조위높이, cm), `min=60` |
| (참고) 실측·예측 실시간 | 해양수산부 국립해양조사원_조위관측소 실측·예측 조위 조회 | [15142507](https://www.data.go.kr/data/15142507/openapi.do) | `https://apis.data.go.kr/1192136/surveyTideLevel/GetSurveyTideLevelApiService` | `bscTdlvHgt`(실측), `tdlvHgt`(예측), cm |

- **관측과 예측:** '1시간 조위(조석성과)'는 관측값을 품질처리(QC)한 **실측** 자료입니다. '조석예보(시계열)'는 **예측** 자료입니다. 실시간 서비스는 품질처리 전의 실측값과 예측값을 같은 행에 줍니다.
- **공통 요청 변수:** `serviceKey`(필수), `obsCode`(필수, 부산 `DT_0005` — 활용가이드 코드표), `reqDate`(yyyyMMdd, 하루 단위), `type=json`, `pageNo`, `numOfRows`(최대 300)
- **호출량:** 개발계정은 서비스별 하루 10,000건입니다. 한 달 수집은 서비스당 약 30건이면 됩니다.
- **문서에 없는 것:**
  - 높이 기준면, 시간대: 미확인
  - 2022년 같은 과거 자료를 주는지: 문서에 없어서 실제 호출로 확인해야 합니다. 하루 시험 조회의 목적이 이것입니다.
- 예전 데이터셋 15038987·15038988·15038990은 공공데이터포털에서 더 이상 열리지 않습니다(404).

## 1. 인증키 신청 (선생님이 한 번만)

1. [공공데이터포털](https://www.data.go.kr)에 일반회원으로 가입하고 로그인합니다.
2. 위 표의 데이터셋 페이지(15156017, 15156022, 필요하면 15142507)에서 각각 **[활용신청]**을 누릅니다.
   - 활용 목적에는 '교육(수업 자료 준비)' 등을 적습니다.
   - 심의 유형이 '자동승인'이라 신청하면 바로 쓸 수 있습니다. 실제 호출이 되기까지 1시간 정도 걸리기도 합니다.
3. **마이페이지 > 오픈API > 개발계정**에서 신청한 서비스를 열면 '일반 인증키'가 보입니다. Encoding과 Decoding 두 가지가 보이는데, 이 도구에는 어느 쪽을 넣어도 됩니다.

## 2. 인증키 설정 (코드나 저장소에 넣지 않기)

인증키를 `index.html`, `js/`, `data/` 같은 학생용 웹앱 파일이나 커밋되는 파일에 쓰지 마세요.

- **Windows PowerShell:** 그 창에서만 유지됩니다.
  ```powershell
  $env:DATA_GO_KR_SERVICE_KEY = "발급받은_인증키"
  ```
- **macOS·Linux 터미널:**
  ```bash
  export DATA_GO_KR_SERVICE_KEY='발급받은_인증키'
  ```
- **파일로 두기:** 저장소의 `.secrets/data-go-kr.key`에 키 한 줄만 넣습니다. `.secrets/`는 `.gitignore`에 들어 있어 커밋되지 않습니다.
- **Claude Code 클라우드 환경:** 환경 설정(Edit)의 환경 변수에 `DATA_GO_KR_SERVICE_KEY`를 추가합니다. 새 세션부터 적용됩니다.
  - 이 API는 키를 주소의 `serviceKey` 변수로만 받습니다. 헤더 방식으로 시험했더니 `SERVICE_KEY_IS_NULL` 오류가 났습니다.
  - 그래서 네트워크 비밀 값(헤더에 넣어 주는 기능)으로는 쓸 수 없고, 환경 변수로 넣어야 합니다.

## 3. 수집

Node.js 18 이상이 필요합니다.

1. 하루 시험 조회. 관측소명, 날짜, 행 수, 값 예시를 출력합니다.
   ```bash
   npm run khoa:test-day
   ```
2. 결과가 맞으면 한 달 수집.
   ```bash
   npm run khoa:collect
   ```
3. 실패한 날이 있으면 같은 명령을 다시 실행합니다. 성공한 날은 건너뛰고 실패·대기한 날만 다시 요청합니다.
4. 원본을 웹앱 사례 파일로 변환합니다.
   ```bash
   npm run khoa:build
   ```
5. 학생 앱의 기본 사례로 쓸 때는 변환할 때 `--set-default`를 붙입니다.
   ```bash
   node tools/khoa/build-case.mjs --start 2022-09-01 --end 2022-09-30 --set-default
   ```

수집 동작 방식:

- 날짜(`reqDate`)를 하루씩 바꾸고, `totalCount`에 이를 때까지 `pageNo`를 늘려 가며 요청합니다.
- 요청 사이에 0.3초씩 쉽니다.
- 일시적 오류(서버 오류, 네트워크 오류, DB_ERROR 등)는 2·4·8초 간격으로 최대 4번 시도합니다.
- 인증키 오류나 하루 호출 한도 초과가 나면 그 즉시 멈추고, 남은 요청을 '대기'로 기록합니다.
- 모든 실패는 `data/raw/khoa/failures.jsonl`에 남깁니다.

## 4. 결과물

| 경로 | 내용 |
|---|---|
| `data/raw/khoa/<자료>/DT_0005/<날짜>/page-<n>.json` | 원본 응답 그대로, 인증키를 지운 요청 주소와 받은 시각 포함 |
| `data/raw/khoa/manifest.json` | 날짜·자료별 상태(ok / nodata / failed / pending) |
| `data/cases/khoa-dt0005-2022-09/observed.csv`, `predicted.csv` | 웹앱이 읽는 시계열 |
| `data/cases/khoa-dt0005-2022-09/case.json` | 관측소, 기간, 출처, 단위, 시간대·기준면 확인 여부 |
| `data/cases/khoa-dt0005-2022-09/quality-report.md` | 누락 구간, 중복, 오류값, 관측소명 확인, 관측·예측 시각 대조 |

변환 규칙:

- 응답에 없는 값은 만들지 않습니다. 결측은 빈 칸으로 두고, 응답에 아예 없는 시각은 행을 만들지 않습니다.
- 같은 시각이 중복되면, 값이 같을 때는 하나만 쓰고 다를 때는 '충돌'로 표시해 값을 비웁니다.
- 높이 기준면을 문서로 확인하지 못했으므로 `datumConfirmed: false`로 기록합니다. 웹앱은 이 경우 잔차(관측 − 예측)를 계산하지 않습니다.
  - 공식 자료로 기준면을 확인하면 `case.json`의 두 데이터셋에서 `datum`을 같은 값으로, `datumConfirmed`를 `true`로 바꾸고, 근거를 `description.datumSource`에 적으세요.
  - 공식 자료의 예: 바다누리에서 내려받은 성과 파일의 머리말, 국립해양조사원 문의 답변
- 달의 위상은 계산값(Meeus)으로 넣습니다. 공식 자료로 확인해 교체하기를 권합니다.
- 태풍 주요 시각, 경로, 기상 자료는 넣지 않았습니다. 기상청 자료로 교사가 입력하세요.

## 기상 자료(기압·풍속·풍향)와 태풍 자료

### 기상: 같은 조위관측소를 먼저 쓰고, 없으면 기상청 ASOS

| 순위 | 서비스 이름 (data.go.kr 활용신청) | 데이터셋 | 받는 값 | 문서로 확인된 것 |
|---|---|---|---|---|
| 1 | 해양수산부 국립해양조사원_조위관측소 실측 기압 조회 | [15142509](https://www.data.go.kr/data/15142509/openapi.do) | `atmpr`(기압) | 단위·기압 종류 미기재, 실시간 서비스(과거 제공 여부 미확인) |
| 1 | 해양수산부 국립해양조사원_조위관측소 실측 풍향/풍속 조회 | [15142518](https://www.data.go.kr/data/15142518/openapi.do) | `wspd`, `wndrct` | 단위 미기재, 실시간 서비스 |
| 2 | 기상청_지상(종관, ASOS) 시간자료 조회서비스 | [15057210](https://www.data.go.kr/data/15057210/openapi.do) | `pa` 현지기압, `ps` 해면기압(hPa), `ws` 풍속(m/s), `wd` 풍향(16방위), QC 플래그 | 부산 지점번호 159, 전일까지 제공 |

- 같은 인증키로 위 서비스를 각각 활용신청합니다(자동승인).
- 하루 시험 조회:
  ```bash
  npm run weather:test-day
  ```
- 한 달 수집:
  ```bash
  npm run weather:collect
  ```
- 사례 파일에 반영:
  ```bash
  npm run khoa:build
  ```
- 변환할 때 조위관측소 기압과 바람이 모두 있으면 그것을 쓰고, 없으면 ASOS를 씁니다. `--weather asos`처럼 직접 고를 수도 있습니다.
- **기압 종류를 섞지 않습니다.**
  - ASOS의 현지기압과 해면기압은 서로 다른 항목(별도 그래프)입니다.
  - 조위관측소 기압은 종류가 문서에 없어 '기압(종류 미확인)'으로 둡니다.
- ASOS의 품질 플래그 1(오류)·9(결측)는 앱에서 결측으로 처리합니다. 빈 시각은 채우지 않습니다.
- **부산 ASOS(159) 지점정보:**
  - 받는 명령:
    ```bash
    npm run kma:station
    ```
  - 결과: 위도 35.10468, 경도 129.03203, 해발 69.56 m. 출처는 기상자료개방포털 지점 상세 페이지이며, 결과는 `data/raw/kma/station/159.json`에 저장됩니다.
  - 조위관측소(35.09638, 129.03527)와의 거리는 약 1 km입니다(두 좌표로 계산).
- 시간대: 기상 자료도 문서에 시간대가 적혀 있지 않아 KST로 해석합니다. 품질 보고서에 '기압 최저 시각 – 태풍 최근접 분석 시각' 차이를 정황 자료로 적습니다.

### 태풍(인증키 불필요)

```bash
npm run kma:typhoon
```

- 기상자료개방포털에서 기상청 자료를 받아 `data/raw/kma/typhoon/2022-11/`에 원본(CP949)을 그대로 보관합니다.
- 받는 자료:
  - **태풍정보**: 시각은 KST(포털 안내).
    - `typhoon_analysis_kst.csv`: 예보시간 0인 행 = 실황 분석 위치. 중심기압·최대풍속·강풍반경 포함.
    - `typhoon_forecast_kst.csv`: 예보시간 12~120시간인 행 = 예보 위치. 70% 확률반경 포함.
  - **태풍경로**: 파일에 시간대가 적혀 있지 않습니다. 같은 위치가 태풍정보(KST)보다 9시간 이른 시각으로 기록되어 있어 UTC로 판단했고, 그 근거를 `meta.json`에 남깁니다.
- 웹앱의 태풍 경로에는 **실황 분석 위치만** 씁니다. 예보 위치는 사례 폴더의 `typhoon_forecast.csv`에 따로 둡니다.
- 사후 재분석한 공식 **베스트트랙**은 기상청 API허브(apihub.kma.go.kr)에서 별도 인증키로 받아야 해서 아직 받지 않았습니다.
- **태풍 중심기압은 태풍 중심의 값**입니다. 부산의 관측 기압으로 쓰지 않으며, 기상 그래프에도 넣지 않습니다.
- **탐구 3 주요 시각:**
  - 거제 부근 상륙(04:50)과 울산 앞바다 진출(07:10): 기상청 발표를 인용한 언론 보도에서 가져왔습니다. 기상청 원 보도자료로 확인하기를 권합니다.
  - 최근접 분석 위치(06:00, 18.9 km): 실황 분석 위치로 계산했습니다.

## 여러 관측소 수집과 비교

활용신청은 관측소별이 아니라 **API 서비스별 한 번**입니다. 같은 서비스에서 관측소 코드만 바꿔 부릅니다.

1. 공식 목록을 받습니다.
   ```bash
   npm run stations:fetch
   ```
   - 국립해양조사원 「조위관측소 운영 현황」(data.go.kr 15146602, 60곳) → `data/raw/khoa/stations/`
   - 기상청 ASOS 관측지점정보(105곳, 이전 이력·해발고도·기압계 높이 포함) → `data/raw/kma/station/`
2. 후보 관측소와 기간을 `tools/khoa/candidates.json`에서 고칩니다. 기간을 바꾸면 다른 연도도 받을 수 있습니다.
3. 계획을 만듭니다.
   ```bash
   npm run stations:plan
   ```
   - 관측소마다 그 기간에 운영한 ASOS 가운데 가장 가까운 곳(최대 40 km)을 따로 고르고, 위치·거리·고도를 `data/stations/plan.json`에 적습니다.
   - 부산 ASOS를 다른 지역에 쓰지 않습니다.
4. 수집합니다.
   ```bash
   npm run multi:test-day
   ```
   ```bash
   npm run multi:collect
   ```
   - 관측소 코드를 바꿔 가며 차례로 요청합니다.
   - 이미 받은 요청(부산 등)은 다시 보내지 않습니다.
   - 한 관측소에 자료가 없거나 오류가 나도 다른 관측소는 계속 받습니다.
   - 인증키 미등록이나 일일 한도 초과는 서비스 단위라서, 그 서비스만 멈추고 '대기'로 남깁니다.
5. 사례를 만듭니다.
   ```bash
   npm run multi:build
   ```
   - 결과: `data/cases/khoa-multi-2022-09/`
     - `case.json`(관측소 목록), `stations/<코드>/`(관측·예측·기상 CSV)
     - `availability.md`(관측소별 자료 확보 현황표)
   - 관측 조위만 있어도 관측소를 제공합니다. 예측·기상이 없으면 앱에 '자료 미제공'으로 표시합니다.
   - 태풍 최근접 분석 시각은 관측소마다 따로 계산합니다.
6. 학생 앱에 연결합니다. `data/cases/index.json`의 `defaultCase`를 바꾸거나 `--set-default`를 붙입니다.

학생 앱:

- 관측소 선택: 지도·목록 대화상자를 시작 화면이나 상단 막대에서 엽니다. 관측소를 바꿔도 이미 만든 근거는 만든 관측소의 자료로 남습니다.
- 두 관측소 비교:
  - 탐구 1(시간별 조위)과 탐구 2(일별 변동 폭)에서 비교할 수 있고, 두 그래프의 시간축이 함께 움직입니다.
  - 세로축은 '개별 눈금'과 '같은 눈금' 중에서 고릅니다.
  - 조위는 관측소마다 기준면이 다르고 아직 확인되지 않았습니다. 그래서 조위 비교의 '같은 눈금'은 **눈금 크기(높이 범위)만 같게** 하고, 축의 숫자는 관측소마다 그대로 둡니다. 숫자만 보고 어느 지역의 해수면이 더 높다고 해석하지 않도록 화면에 안내합니다.
  - 일별 변동 폭은 기준면과 무관한 '차이'라서 같은 축으로 비교합니다.
- 근거와 PDF: 관측소 코드·해역, 비교 관측소와 눈금 방식, 관측소별 자료 출처(기상 관측 지점과 거리)가 들어갑니다.
- 학생 앱은 미리 만든 파일만 읽습니다. 관측소를 바꿀 때도 외부 API를 부르지 않습니다.

## API가 2022년 자료를 주지 않을 때 (수동 내려받기 경로)

바다누리 해양정보 서비스에서 같은 '1시간 조위(조석성과)'를 월별 파일로 받을 수 있습니다(로그인 필요).

1. [바다누리 해양정보 서비스](https://www.khoa.go.kr/oceandata/main.do)에 로그인하고 **[내려받기]**로 갑니다.
2. 자료구분 **조석 성과** → 자료 종류 **1시간 조위** → 자료 유형 **월별** → 관측소 유형 **조위관측소** → 관측소 **부산** → 연도 **2022** → [검색]
3. 목록에서 2022년 9월(필요하면 8월·10월) 파일을 [다운로드]합니다.

- 안내문에 따르면 통계자료는 최종 품질처리 후 익월 15일 이후에 제공됩니다. 또 "조석기준면 결정 전 자료는 참고용"이라는 주의가 있습니다.
- 내려받은 파일의 형식(열 구성, 머리말에 기준면이 적혀 있는지)은 아직 확인하지 못했습니다. 파일 하나를 주시면 변환기를 그 형식에 맞춰 추가하겠습니다.

## 수행평가 자료(인천·부산·묵호 2025-10~2026-09) — 형식 3 사례

1. 관측소 계획: `data/stations/plan-2025-26.json`(인천 DT_0001·ASOS 112, 부산 DT_0005·ASOS 159, 묵호 DT_0006·ASOS 106 동해).
2. 수집: 관측소×(조위|기상) 6개 작업을 나눠 `data/raw-work/par/<관측소>-<tide|wx>/`(git 제외)에 받았습니다(5,475건 모두 정상).
3. 원본 보관: 낱개 응답을 자료·관측소·월별 gzip 묶음으로 `data/raw/khoa-2025-26/packs/`에, 합친 수집 기록을 `manifest.json`에 둡니다(`tools/lib/rawpack.mjs`). 빌드 도구는 낱개 파일이 없으면 묶음에서 같은 경로를 읽습니다. URL의 인증키는 `serviceKey=***`로 가려져 있습니다.
4. 시간대 확인: `node tools/khoa/check-time-basis.mjs --fetch`(공식 자료를 받아 `time-check/reference/`에 저장, PDF 글자 추출에 `pdftotext` 필요) 또는 인수 없이(저장해 둔 자료로 다시 비교). 결과는 `data/raw/khoa-2025-26/time-check/README.md`·`result.json`. 시각은 고치지 않고 보고만 합니다.
5. 사례 만들기: `node tools/khoa/build-assess.mjs` → `data/cases/khoa-assess-2025-26/`. 부산 2022년 9월(관측 조위·ASOS)은 기존 원본 `data/raw/khoa/`에서, 태풍 힌남노는 `data/raw/kma/typhoon/2022-11/`(실황 분석 위치, KST)에서 가져옵니다. 탐구 4 기간 B 주변 태풍 확인 자료는 `data/raw/kma/typhoon/2026-09-check/`(거리만 사용).
6. 10분 간격 예측(탐구 1): 같은 조석예보(시계열) API에 `min=10`을 주는 `forecast10` 자료입니다. 부산 2026년 9월만 받았습니다(`node tools/khoa/collect.mjs --station DT_0005 --datasets forecast10 --start 2026-09-01 --end 2026-09-30 --out data/raw-work/f10-2026-09`, 30회 호출). 정시 값은 1시간 예측과 모두 같습니다. 2022년 9월은 이 API가 예측 자료를 주지 않습니다(NODATA — 예측은 2025년 1월부터 제공).
