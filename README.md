# 조석 데이터 탐구실

고등학교 지구과학 수행평가용 웹앱입니다. 학생은 교사가 미리 넣어 둔 조석 자료를 분석하고, 답안을 쓰고, 분석 그래프와 답변이 들어간 PDF 보고서를 내려받습니다.

- 흐름: 시작 → 탐구 1(하루의 규칙) → 탐구 2(한 달의 규칙) → 탐구 3(태풍의 영향) → 종합 결론 → 보고서 미리보기·PDF
- 회원가입, 서버 전송, 외부 자료 검색은 없습니다. 답안은 **현재 브라우저(localStorage)** 에만 저장되고, PDF도 브라우저 안에서 만들어집니다.
- 빌드 과정이 없는 정적 웹앱입니다(HTML·CSS·JavaScript 모듈). 학교 웹 서버, GitHub Pages, Vercel 같은 정적 호스팅에 폴더를 그대로 올리면 됩니다.

> ⚠ 지금 들어 있는 자료는 **기능 확인용 예시 데이터**(가상 관측소·가상 태풍, 2099년)입니다. 화면과 PDF에 계속 그렇게 표시됩니다. 실제 수업 전에 아래 방법으로 실제 자료로 바꾸세요.

## 실행

```bash
npm start
```

브라우저에서 `http://localhost:8080/`을 엽니다. `index.html`을 파일로 더블클릭해서 열면 자료를 읽을 수 없으니 반드시 웹 서버로 여세요.

## 실제 자료로 바꾸기

관측소 이름, 기간, 태풍 이름은 화면 코드에 직접 쓰지 않고 **사례 설정(`case.json`)** 에서만 관리합니다.

1. `data/cases/` 아래에 새 폴더를 만듭니다. 예: `data/cases/busan-2022/`
2. 자료 파일(CSV)을 넣습니다. 열 이름은 자유이며 `case.json`에서 알려 주면 됩니다.
   - 관측 조위(필수): 시각, 조위, (선택) 품질 코드
   - 천문조 예측 조위(선택): 시각, 예측 조위
   - 기상(선택): 시각, 기압, 풍속, 풍향
   - 달의 위상(선택): 시각, 위상 이름(삭/상현/망/하현 또는 new/first/full/last), (선택) 음력
   - 태풍 경로(선택): 시각, 위도, 경도, 중심기압, 최대풍속
3. `sample-2099/case.json`을 복사해 고칩니다. 주요 항목:

| 항목 | 뜻 |
|---|---|
| `id`, `dataVersion` | 사례 식별자, 자료 버전(백업 파일과 근거에 기록됨) |
| `isSample` | 실제 자료라면 `false`. `true`이면 화면·PDF에 “기능 확인용 예시 데이터”가 표시됨 |
| `timezone.offsetMinutes` | 화면 표시 시간대(KST = 540) |
| `station` | 조위 관측소 이름·좌표 |
| `description` | 제공 기관, 자료명, 기간, 관측 간격, 기준면, 식별자(보고서의 자료 출처에 표시) |
| `datasets.observed.time.offset` | **원자료** 시각의 시간대. UTC 자료면 `"+00:00"` |
| `datasets.*.unit` | 원자료 단위 `cm`/`m`/`mm`. 앱이 cm로 명시적으로 변환하고 변환 내역을 보고서에 적음 |
| `datasets.*.stationId`, `datum` | 관측·예측 자료가 같은 관측소·같은 기준면인지 확인하는 값. 다르면 잔차를 계산하지 않음 |
| `datasets.observed.quality` | 품질 코드 → 정상/의심/오류/결측. 오류·결측은 빈 값으로 처리(0으로 바꾸지 않음) |
| `missingValues`, `valueRange` | 결측 표시 문자열, 허용 범위(벗어나면 오류값으로 결측 처리) |
| `datasets.<이름>.provided: false` | 자료가 없을 때. 해당 그래프·문항에 “자료 미제공”이 표시되고 값을 만들지 않음 |
| `inquiry1`, `inquiry2`, `inquiry3` | 탐구별 기간. `inquiry3.keyTimes`는 그래프에 표시할 태풍 주요 시각 |

4. `data/cases/index.json`의 `cases`에 새 사례를 추가하고 `defaultCase`를 바꿉니다. `enabled: false`인 사례는 `?case=사례id`로만 열 수 있습니다.
5. 열 이름만 다른 CSV는 `case.json` 수정만으로 됩니다. 파일 형식 자체가 다르면(엑셀, 고정폭 텍스트 등) `js/data/normalize.js`에 변환 함수를 추가하세요. 화면 코드는 고칠 필요가 없습니다.
6. 기준면 변환이나 시각 보정이 필요하면 앱 밖에서 미리 처리한 파일을 넣으세요. 앱은 가까운 시각을 이어 붙이거나 보간하지 않습니다.

## 자료 처리 기준

- 내부 시각은 UTC, 조위는 cm로 통일하고, 화면에는 사례 시간대로 표시합니다.
- 결측·오류값은 `null`로 두고 그래프 선을 끊습니다. 관측점은 직선으로만 잇습니다.
- 일별 해수면 변동 폭 = 해당 날짜(00:00~24:00)의 관측 최고값 − 관측 최저값. 자료가 빠진 날은 “불완전”으로 표시하고 비교에서 구분합니다.
- 조위 잔차 = 같은 시각의 관측 조위 − 예측 조위. 같은 관측소·같은 기준면·같은 단위일 때 시각이 정확히 같은 값끼리만 계산합니다.
- 1시간 간격 자료의 최고값은 “관측값 중 최고값”으로 표시합니다.

## 저장과 개인정보

- 저장 위치: 현재 컴퓨터의 브라우저(`tideLab.`으로 시작하는 localStorage 키). 외부 서버로 보내지 않습니다.
- [저장·백업] 메뉴: 백업 파일(JSON) 받기와 불러오기, “이 컴퓨터의 내 작성 내용 삭제”(이 앱의 키만 삭제).
- 백업 파일을 불러올 때 형식, 버전, 사례 id, 자료 버전을 확인합니다. 실패하면 기존 답안은 그대로 둡니다.

## PDF

- `pdf-lib`로 브라우저 안에서 A4 세로 PDF를 만듭니다. 한글 글꼴을 PDF에 넣으므로 다른 컴퓨터에서도 글자가 깨지지 않습니다. 본문은 검색·복사할 수 있는 텍스트이고, 그래프는 벡터로 그려 인쇄해도 선명합니다.
- 글꼴 파일은 Noto Sans KR에서 한글·기본 기호만 남긴 버전입니다(약 2.6 MB). pdf-lib의 글꼴 부분 포함 기능에서 글자가 빠지는 문제가 있어 글꼴 전체를 넣으며, 그래서 PDF는 약 2 MB입니다. 글자 대체 규칙(GSUB/GPOS)을 지운 것도 pdf-lib 숫자 간격 문제를 피하기 위해서입니다.
- 파일 이름: `조석탐구_3학년2반15번_김학생.pdf`

## 검증

```bash
npm test
```

```bash
npm run test:e2e
```

- `npm test`: 데이터 처리 단위 검증(시간대·날짜 경계, 결측·오류값, 음수, 단위 변환, 일별 변동 폭, 잔차의 시각·기준면 확인 등).
- `npm run test:e2e`: Playwright로 전체 흐름을 검증합니다. 학생 정보 입력, 지점 선택과 계산값(원자료와 대조), 근거 고정, 새로고침 복구, 백업·삭제·불러오기, PDF 내용(한글·줄바꿈·긴 답변·쪽 번호·그림 번호), 자료 미제공 사례가 포함됩니다. `pdftotext`가 필요합니다.

예시 자료를 다시 만들려면 다음을 실행합니다.

```bash
npm run make-sample
```
