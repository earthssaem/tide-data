# 조석 데이터 탐구실

고등학교 지구과학 수행평가용 웹앱입니다. 학생은 미리 수집해 둔 **실제 관측 자료**(국립해양조사원 예측·관측 조위, 기상청 ASOS, 기상청 태풍정보)를 그래프에서 읽고, 지점·날짜·구간을 고르고, 짧은 답과 그림을 써서 PDF 보고서를 내려받습니다.

- 자료: 인천(서해)·부산(남해, 대표)·묵호(동해) 2025년 10월~2026년 9월의 1시간 예측·관측 조위, 부산 2026년 9월 10분 간격 예측 조위(탐구 1), 부산 ASOS 기상, 부산 2022년 9월(관측 조위·기상·태풍 힌남노 경로).
- 학생 흐름(관측소 선택 단계 없음): 학생 정보 → 탐구 1 조석의 규칙(부산 예측 조위, 문항 ①~④, [달의 위상 확인]) → 탐구 2 지역별 차이(세 지역 예측 조위, ⑤⑥) → 탐구 3 특이한 변화(부산 관측 조위 두 기간, ⑦⑧ → [추가 자료 확인] → ⑨) → 종합(⑩) → 보고서·PDF.
- 원인(기상·태풍)과 달의 위상은 처음에 알려 주지 않습니다. 탐구 1의 [달의 위상 확인], 탐구 3의 [추가 자료 확인]을 누른 순간의 답을 보관·고정한 뒤에만 열립니다.
- 회원가입, 서버 전송, 외부 API 호출은 없습니다. 학생 답은 **현재 브라우저(localStorage)** 에만 저장되고, PDF도 브라우저 안에서 만들어집니다.
- 빌드 과정이 없는 정적 웹앱입니다(HTML·CSS·JavaScript 모듈). 교사 로그인만 Vercel 서버 기능(`api/`)을 씁니다.

> 현재 학생용 배포 설정(`data/assessment.json`)은 **임시 후보(교사 검토 필요)** 입니다. 분석 연월 2026-09, 탐구 1 구간 9/10~12(문항 ②의 24시간 9/11), 탐구 2 같은 3일, 탐구 3 기간 A 2022-09-04~08 · 기간 B 2022-09-25~29. 교사용 화면에서 검토한 뒤 확정하세요.

### 문항과 화면

| 탐구 | 그래프·기능 | 문항(답 형식) |
|---|---|---|
| 1 조석의 규칙 | 부산 예측 조위 3일 — **10분 간격**(만조·간조가 정시 사이에 있으므로; 10분 자료가 없는 달은 1시간 간격과 안내), 문항 ②의 24시간 색칠, 그래프를 누르면 가장 가까운 자료점의 시각·높이 / 한 달 예측 조위(1시간 간격 점을 이은 선, 누르면 그날 선택) | ① 이웃한 만조·간조 하나씩 고르기 + 조차 `___cm`(학생 계산) ② 만조 `___회`/간조 `___회`/약 `___시간` ③ 대조·소조 날짜 하나씩(마우스를 올리면 그날 하루가 색칠, 날짜 글자는 그날 가운데) ④ 대조·소조 배치판 두 칸(태양·지구 고정, 달 1·달 2를 공전 궤도 위에서 끌기 — 조위 자료만으로는 달이 궤도의 어느 쪽인지 하나로 정할 수 없으므로 있을 수 있는 위치를 모두 나타냄, 키보드: Tab + 화살표) + 조차가 크고 작은 이유 → [달의 위상 확인]: ③④ 고정, 이후 위상 표시 |
| 2 지역별 차이 | 인천·부산·묵호 예측 조위(같은 시간 축). [같은 축(평균 0)]: 지역마다 이 기간 평균을 0으로 해 세 그래프를 똑같은 세로축에(조차를 같은 숫자로 비교, 기준면이 달라도 높낮이 비교가 되지 않음) / [개별 눈금]: 원래 값. 관측소 지도, 기준면 주의 문구 | ⑤ 조차 큰 순서 `___ > ___ > ___` ⑥ 지역별 [반일주조/혼합조/일주조/판단 어려움] + 근거 한 줄 |
| 3 특이한 변화 | 공개 전: 부산 관측 조위 기간 A·B(둘 다 2022년 9월 — 기본값 A 9/4~8, B 9/25~29, 실제 날짜, 같은 눈금 크기). 공개 후: 두 기간의 ASOS 해면기압·풍속(같은 시간 축, 학생 부담을 줄이려고 풍향은 뺌), 누른 시각의 값 표(시각 연결), 기상 지점 안내(기상청 부산 ASOS는 조위관측소에서 약 1 km — 2022년 9월에는 조위관측소 기상 자료가 없어 두 기간 모두 ASOS, 1년 비교에서 기압 차 0.4 hPa 이내·바람은 지점 차이 있음), 태풍 경로 지도·최근접 분석 시각, 기간마다 앞뒤 하루 포함 가장 가까웠던 태풍(기상청 태풍경로, 거리), 주의 문구 | ⑦ 차이 한 문장 ⑧ 원인 추측 한 문장 → [추가 자료 확인]: ⑦⑧ 고정 → ⑨ 기상·태풍 자료에서 근거를 하나 이상 들어 설명(1~2문장, ⑧을 위에 표시) |
| 종합 | 탐구별 내 답 다시 보기 | ⑩ 해수면 높이에 영향을 주는 요인 정리(1~2문장) |

- 예측 조위 안내 문구: “해당 지역의 조석 특성과 달·태양의 주기적인 영향을 바탕으로 계산한 해수면 높이입니다.”
- 기간 B는 [추가 자료 확인] 뒤에만 “확인한 기압·바람이 상대적으로 안정적인 기간”으로 표시합니다(공개 전에는 날짜만).
- ‘근거 추가’ 버튼은 없습니다. 학생이 고른 지점·날짜·구간은 저장되고, 보고서·PDF의 해당 그래프에 자동으로 그려집니다(같은 그래프를 쓰는 문항은 그림 하나를 함께 씀).

## 주소(모드)

| 주소 | 용도 |
|---|---|
| `/` | 학생용. `data/assessment.json`에 켠 실제 관측소·기간만 씁니다. 자료를 못 읽으면 오류와 [다시 시도]만 보이고, 예시 자료로 바꾸지 않습니다. |
| `/?mode=teacher` | 교사용 평가 설정 화면. **교사 로그인 필요**(학생 화면에는 이 주소로 가는 링크가 없습니다). |
| `/?mode=preview` | 교사용 미리보기. **교사 로그인 필요**. 교사 설정을 적용하며, 작성 내용은 학생 답안과 따로 저장됩니다. |
| `/?mode=preview&case=sample-2099` | 기능 시험(가상 데이터, 교사 로그인 필요). 가상 데이터는 이 방법으로만 열립니다. |

## 교사 로그인(Vercel 서버 기능)

교사용 설정·미리보기는 비밀번호로 로그인해야 열립니다. 학생 화면(`/`)은 로그인 없이 그대로이며, 학생 정보·답안은 지금처럼 학생 브라우저에만 저장되고 서버로 보내지 않습니다.

- 서버 기능: `api/teacher/login`·`session`·`logout`·`setup` (Vercel Functions, Node 내장 기능만 사용).
- 비밀번호: 저장소·HTML·JS·JSON 어디에도 없습니다. 서버 환경변수에 **scrypt 검증값**만 두고 서버에서 확인합니다(브라우저는 정답을 비교하지 않음). 로그인은 HTTPS POST 본문으로만 보내며 비밀번호와 본문은 로그에 남기지 않습니다.
- 세션: 서명된 토큰을 만료 시간(기본 8시간)이 있는 `__Host-` 쿠키(HttpOnly·Secure·SameSite=Strict)로 보냅니다. [로그아웃]으로 지웁니다.
- 보호: 교사용 비공개 정보(서버에 보관한 교사 설정·메모)를 읽고 쓰는 요청은 서버가 매번 세션을 확인하고, 변경 요청은 같은 출처(Origin)와 CSRF 토큰도 확인합니다. 화면 버튼을 숨기는 것이 아니라 서버가 거부합니다.
- 시도 제한: 같은 곳에서 15분에 5번, 전체 15분에 100번 실패하면 잠시 막습니다(429). 실패마다 최소 0.6초 지연, scrypt 계산 비용도 있습니다.
- 환경변수가 없거나, 형식이 틀리거나, 서버 저장소에 문제가 있으면 접근을 허용하지 않습니다(교사 화면은 “열 수 없습니다”, 미리보기는 오류).

**공개되는 것과 비공개인 것을 구분하세요.** 로그인은 서버 API와 그 뒤의 교사용 정보만 보호합니다.

| 공개(로그인과 무관, 누구나 내려받을 수 있음) | 비공개(교사 로그인 필요) |
|---|---|
| 저장소 코드 전체(교사 화면 코드 포함), `data/` 아래 모든 자료(사례 파일의 태풍 정보, `data/assessment.json` 등), 글꼴·라이브러리 | 서버 저장소에 보관한 교사 설정과 **교사용 메모**, 교사용 API의 응답 |

학생이 탐구 3의 [추가 자료 확인] 전에 원인을 알지 못하게 하는 것은 화면 구성(공개 단계) 수준이며, 파일 자체를 숨기지는 않습니다. 교사만 봐야 할 자료를 새로 만든다면 `data/`나 저장소의 공개 파일에 넣지 말고 서버 저장소(로그인으로 보호된 API)에 두세요.

### Vercel 설정 순서

1. **비밀번호 검증값 만들기(선생님 컴퓨터에서)**: 저장소 폴더에서 `npm run teacher:setup`을 실행하고 비밀번호(12자 이상)를 두 번 입력합니다. 입력은 화면에 보이지 않고 셸 기록에도 남지 않습니다. 출력된 `TEACHER_PASSWORD_HASH=…`, `TEACHER_SESSION_SECRET=…` 두 줄을 복사합니다(비밀번호 자체가 아님). 이 값들도 저장소·채팅·메신저에 붙여 넣지 마세요.
2. **환경변수 넣기**: Vercel → 프로젝트 → Settings → Environment Variables에서 아래를 추가합니다. Environment는 Production(필요하면 Preview도), **Sensitive**를 켭니다.
   - `TEACHER_PASSWORD_HASH` (필수)
   - `TEACHER_SESSION_SECRET` (필수)
   - `TEACHER_SESSION_HOURS` (선택, 1~24, 기본 8)
3. **서버 저장소 연결(권장)**: Vercel → Storage(또는 Marketplace) → Upstash Redis를 만들어 이 프로젝트에 연결하면 `UPSTASH_REDIS_REST_URL`·`UPSTASH_REDIS_REST_TOKEN`(또는 `KV_REST_API_URL`·`KV_REST_API_TOKEN`)이 자동으로 들어갑니다. 연결하면 시도 제한이 모든 서버 인스턴스에서 공유되고, 로그아웃한 세션이 즉시 무효화되며, 교사 설정·메모가 로그인으로 보호된 서버에 저장됩니다. 연결하지 않으면 시도 제한은 인스턴스마다 따로(재시작 시 초기화) 동작하고, 교사 설정은 그 브라우저에만 저장됩니다.
4. **재배포**: 환경변수는 새 배포부터 적용됩니다. Deployments → 최신 배포 → ⋯ → Redeploy를 누르거나 `main`에 새 커밋을 올립니다.
5. **확인**: `https://<배포 주소>/?mode=teacher`에서 로그인 → 설정 화면 → [로그아웃]. 틀린 비밀번호를 5번 넣으면 잠시 막히는 것도 확인할 수 있습니다.

- 비밀번호를 바꾸려면 1~2를 다시 하고 재배포합니다. `TEACHER_SESSION_SECRET`을 바꾸면 이미 로그인한 모든 세션이 끝납니다.
- 로컬 확인: `npm run teacher:setup -- --write-local`로 `.env.local`(git 제외)을 만든 뒤 `npm start`. 이름만 있는 예시는 `.env.example`입니다.
- GitHub Pages처럼 서버 기능이 없는 호스팅에서는 교사 화면이 열리지 않습니다(학생 화면은 동작).

## 교사용 평가 설정

`/?mode=teacher`에서 로그인한 뒤 다음을 정합니다. 그래프 미리보기와 검증 결과가 바로 나옵니다.

- 문항 켜기·끄기(①~⑩, 끈 문항은 학생 화면·보고서에서 빠지고 번호는 유지), 검토 완료 표시
- 기본 분석 연월(2025-10~2026-09): 탐구 1의 한 달 그래프에 씀. 바꾸면 탐구 1·2 구간이 그달 10일부터 3일로 옮겨집니다.
- 탐구 1: 3일 구간의 시작일·길이, 문항 ②의 24시간 시작 시각(만조·간조와 겹치지 않게 고르기)
- 탐구 2: 지역 비교 기간(시작일·길이, [탐구 1과 같은 기간])
- 탐구 3: 비교 기간 A·B의 시작일·길이(부산 2022년 9월 또는 2025-10~2026-09 안). 기간마다 가장 가까웠던 태풍 거리가 함께 표시됩니다.
- 교사용 메모(학생 화면·학생 PDF·학생용 배포 파일에 들어가지 않음)
- 앱 개편 전(설정 형식 2)에 저장한 교사 설정은 교사 화면을 열 때 새 기본값(학생용 배포 설정)으로 바뀌고 저장됩니다. 메모는 그대로 옮기고, 이전 값은 화면 위쪽 표로 보여 줍니다. 미리보기는 개편 전 설정을 쓰지 않습니다.
- 저장된 교사 설정이 학생용 배포 설정과 다르면(앱이 바뀌어 배포 기본값이 달라진 경우 등) 위쪽에 다른 항목 표가 나오고, [배포 설정 값으로 맞추기](메모 유지)로 한 번에 맞출 수 있습니다.

검증: 구간이 분석 연월·자료 범위 안에 있는지, 결측, 기간 A·B의 관측 조위·해면기압·풍속 확보 수, 시간대 확인 여부. 대조·소조·조석 형태의 정답을 지정하는 기능은 없습니다.

**저장과 학생 적용은 다릅니다.**

1. 교사용 화면에서 바꾼 내용은 자동 저장되고 [학생용 미리보기]에만 적용됩니다. 서버 저장소가 연결되어 있으면 로그인으로 보호된 서버에(이 브라우저에는 메모를 뺀 사본), 없으면 이 브라우저(`tideLabTeacher.v1.setup`)에만 저장됩니다.
2. 학생에게 적용하려면 [설정 저장·내보내기] → **학생용 배포 파일(assessment.json)** 을 받아 저장소의 `data/assessment.json`을 그 파일로 바꾸고 배포(`main` 반영)합니다. 학생 화면을 새로 고치면 적용됩니다.
3. **교사 보관용 파일**(메모 포함)을 받아 두면 다른 컴퓨터에서 [설정 파일 불러오기]로 이어서 고칠 수 있습니다. [학생용 배포 설정으로 되돌리기]는 이 브라우저의 교사 설정을 지우고 배포 설정을 다시 읽습니다.

다른 기간은 `tools/khoa`로 수집한 뒤 `tools/khoa/build-assess.mjs`와 같은 방식으로 형식 3 사례(`data/cases/<id>`)를 만들면 교사용 화면의 사례 목록에 나타납니다.

## 실행

```bash
npm start
```

브라우저에서 `http://localhost:8080/`을 엽니다. `index.html`을 파일로 더블클릭해서 열면 자료를 읽을 수 없으니 반드시 웹 서버로 여세요.

## 실제 자료로 바꾸기

국립해양조사원·기상청 자료는 `tools/khoa/`의 자동 수집 도구로 받습니다(인증키 신청·설정·실행: [tools/khoa/README.md](tools/khoa/README.md)). 사례 파일은 다음으로 만듭니다.

```bash
node tools/khoa/build-assess.mjs
```

- 결과: `data/cases/khoa-assess-2025-26/case.json`(형식 3) + 관측소별 CSV + `availability.md`(자료 확보 현황, 날마다 관측·예측 시각 어긋남 검사 — 표시만 하고 시각은 고치지 않음)
- 관측소 이름·기간·태풍 이름은 화면 코드가 아니라 `case.json`에서 관리합니다. 자료가 없으면 `provided: false`로 두고, 화면·보고서는 ‘자료 미제공’으로 표시합니다(값을 만들지 않음).
- `case.json`의 `timeBasis.confirmed`가 `true`일 때만 탐구 3의 시각 연결(조위·기압·바람·태풍 시각 함께 보기)이 켜집니다. 이 값은 시간대 확인 결과(`data/raw/khoa-2025-26/time-check/result.json`)가 모두 ‘확인’일 때만 `true`가 됩니다.

### 시간대 확인(2026-11-08)

```bash
node tools/khoa/check-time-basis.mjs
```

공공데이터포털 문서에는 시간대가 적혀 있지 않아, 시각이 적힌 공식 자료와 **같은 시각의 값**을 비교했습니다(그래프 모양 비교만으로 판단하지 않음). −12~+12시간 어긋남을 모두 시험해 0시간이 유일한 최적인지 봅니다.

| 자료 | 대조한 공식 자료 | 결과 |
|---|---|---|
| 예측 조위(인천·부산·묵호) | 국립해양조사원 조석표 PDF(표지 “시 각 : 9hE”)의 매시 예측 조고 | 각 8,760시각 모두 반올림 값 일치, 0시간 |
| 관측 조위 | 바다누리 해양정보 관측값(실시간 표시 시각이 KST임을 받은 시각과 비교해 확인) | 0시간(5분 단위로도 0분), 1시간 자료는 짧은 출렁임을 거른 값 |
| 조위관측소 기압·풍속 | 바다누리 해양정보 관측값 | 모든 시각 같은 값, 0시간 |
| ASOS(활용가이드에 시간대 없음) | 일사량과 계산한 태양 위치 / 조위관측소 기압의 1시간 변화량 | 둘 다 0시간(UTC 가정 시 상관이 음수) |
| 태풍정보 | 기상자료개방포털 안내 “시간 단위: KST” | KST |

조석표의 기준면 표기(인천 평균해면 아래 464 cm, 부산 65 cm, 묵호 19 cm)는 예측 조위에 해당합니다. 관측 조위의 기준면은 문서에 없어 확인되지 않은 것으로 둡니다.

## 자료 처리 기준

- 내부 시각은 UTC, 조위는 cm로 통일하고, 화면에는 KST로 표시합니다. 시각은 그래프 모양을 보고 고치지 않습니다.
- 결측·오류값은 `null`로 두고 그래프 선을 끊습니다. 관측점은 직선으로만 잇습니다.
- 일별 변동 폭 = 그날(00:00~24:00) 1시간 간격 값의 최고 − 최저. 자료가 빠진 날은 ‘불완전’으로 구분합니다.
- 기준면이 확인되지 않은 자료: 시각과 변동 폭만 비교하고 관측소끼리·예측과 관측끼리 높이를 비교하지 않습니다(같은 눈금 크기 = 세로 눈금 간격만 같고 각자 가운데). 시간대가 확인되지 않으면 시각 비교를, 단위가 확인되지 않으면 숫자 비교를 보류합니다.
- 기압은 해면기압만 쓰고 현지기압과 한 축에 섞지 않습니다. 태풍 중심기압은 관측소 기압으로 쓰지 않습니다.

## PDF

- `pdf-lib`로 브라우저 안에서 A4 세로 PDF를 만듭니다. 한글 글꼴을 PDF에 넣으므로 다른 컴퓨터에서도 글자가 깨지지 않습니다. 본문은 검색·복사할 수 있는 텍스트이고, 그래프는 벡터로 그려 인쇄해도 선명합니다.
- 글꼴 파일은 Noto Sans KR에서 한글·기본 기호만 남긴 버전입니다(약 2.6 MB). pdf-lib의 글꼴 부분 포함 기능에서 글자가 빠지는 문제가 있어 글꼴 전체를 넣으며, 그래서 PDF는 약 2 MB입니다. 글자 대체 규칙(GSUB/GPOS)을 지운 것도 pdf-lib 숫자 간격 문제를 피하기 위해서입니다.
- 파일 이름: `조석탐구_3학년2반15번_김학생.pdf`

## 전체화면 평가 모드

수행평가 시간에 전체화면에서만 진행하도록 돕는 기능입니다. 기존 탐구 기능과 분리된 모듈입니다.

- 파일: `js/assessment/assessment-mode.js`(화면·이벤트), `js/assessment/session-log.js`(기록 규칙), `js/assessment/config.js`(설정), `css/assessment.css`
- 접속하면 **평가 시작 안내**가 앱을 가립니다. [평가 시작]을 눌러 전체화면 진입에 **성공해야만** 평가가 시작됩니다.
- 평가 중 다음을 감지하면 즉시 기록하고 **평가를 일시 중지**합니다. 불투명 화면으로 콘텐츠를 가리고, 마우스·키보드 입력을 막습니다(`inert`).
  - 전체화면 해제(`fullscreenchange`): 즉시
  - 화면 숨김(`visibilitychange`, 탭 전환·최소화 등): 즉시
  - 창 포커스 상실(`blur`/`focus`, Alt+Tab 등): 2초 이상 이어질 때
  - 페이지 이탈(`pagehide`, 새로고침·닫기): 가능한 범위에서
- [전체화면으로 복귀]로 전체화면 진입에 성공해야만 재개됩니다. 실패하거나 취소하면 중지 상태가 유지됩니다.
- 한 행동에서 여러 이벤트가 생겨도(예: blur → 숨김 → 전체화면 해제) **이탈 1회**로 집계하고, 각 이벤트는 그 사건의 신호로 남깁니다.
- 새로고침이나 재접속을 하면 같은 세션을 복원하고, 전체화면으로 복귀하기 전까지 중지 상태를 유지합니다. 종료 신호가 남지 않은 비정상 종료는 '재접속'으로 기록하며, 이탈 시작 시각은 10초마다 기록한 마지막 확인 시각으로 추정합니다.
- 정상 종료: 화면 아래 [평가 종료] → 확인 → 전체화면 해제, 감지 중지(이탈로 집계하지 않음) → 기록 JSON 다운로드
- 기록 위치: localStorage `tideLabAssess.v1`(세션별). 앱의 '이 컴퓨터의 내 작성 내용 삭제'(`tideLab.` 키)로는 지워지지 않습니다.
- 기록 JSON: 세션 ID, 시작·종료 시각, 이탈 횟수, 사건별 유형·이탈 시각·복귀 시각·지속 시간·신호 목록, 학생 정보(앱 저장 내용에서 읽음)
- 연습용으로 끄려면 `js/assessment/config.js`의 `enabled`를 `false`로 바꿉니다.

**한계(기록 해석 시 주의)**

- 브라우저 보안 정책상 전체화면 종료 자체는 막을 수 없습니다. 종료를 감지해 기록하고 중지할 뿐입니다.
- 브라우저 이벤트만으로 이탈 원인이나 다른 프로그램 사용 여부를 알 수 없습니다. 유형은 '관찰된 신호'입니다.
- 브라우저 강제 종료, 전원 차단 등에서는 일부 이벤트가 기록되지 않을 수 있습니다.
- 기록은 학생 컴퓨터에 저장되므로 개발자 도구 등으로 수정될 수 있습니다. 무결성이 보장되지 않습니다.
- 이 기록만으로 부정행위를 판정하거나 감점하지 마십시오.
- 앱 기능이 띄우는 창(파일 선택, 다운로드 저장 창, 인쇄)으로 생긴 짧은 포커스 상실은 이탈로 세지 않고 `appDialogNotes`에 따로 남깁니다. 그 사이 전체화면이 해제되면 이탈로 기록합니다.

**기존 코드 변경 사항**

- `index.html`: `css/assessment.css` 연결, `js/assessment/assessment-mode.js` 스크립트 추가(앱보다 먼저 실행)
- `js/main.js`: `tidelab:assessment-pause` 이벤트를 받으면 입력 중인 답안을 즉시 저장(`app.store.flush()`). 기존 자동 저장과 같은 경로입니다.
- 중지되는 순간 열려 있던 앱 대화상자(확인 창 등)는 '취소'로 닫힙니다(최상위 층 대화상자가 가림 화면 위로 보이지 않게 하기 위함).
- 연결 지점: `document`에 `tidelab:assessment-start`, `-pause`, `-resume`, `-end` 이벤트를 보내고, `window.TideAssessment.isPaused()`, `.getState()`, `.onChange(fn)`을 제공합니다. 기존 앱에는 타이머나 자동 진행이 없어 추가로 멈출 기능은 없습니다.
